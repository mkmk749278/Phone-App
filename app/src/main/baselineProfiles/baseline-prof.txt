# Baseline profile for DualShieldPhone.
#
# These rules tell ART to compile the listed classes and methods ahead of time when the app
# is installed, instead of interpreting them until the JIT warms up. That matters most for
# the first launch and the first scroll, which is exactly where the app felt slowest.
#
# Prefix meanings: H = hot, S = startup, P = post-startup, L = a class reference.
#
# This is a hand-written profile covering the app's own startup and list-scrolling paths. A
# profile generated from a real device run with the androidx.baselineprofile plugin would be
# more precise; this is the portion that can be written correctly without one, and it is
# additive — an imprecise rule costs a little install-time compilation, never correctness.
